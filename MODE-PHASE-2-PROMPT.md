# Mode phase 2 — receive parity, transmit parity, then wire them in

**Paste this whole file into a fresh session, or point the session at it.** It is
the brief for the work after [`MODE-PROGRESS.md`](MODE-PROGRESS.md), which closed
the first pass: every corpus mode has a verdict, but 54 of 157 decode and only a
few of those are selectable in the program.

   what exists.

## Current truth, so nothing is re-derived

- Every mode fldigi can send has been measured; **54 of 157 decode their own sample**.
- **Working decoders that are not yet modes in the program:** MFSK (11 variants),
  MT63 (2K only), Contestia (18/19 variants), ARDOP (modem/PHY only). `Mode` has
  Thor, Fsq, Hell, Olivia, Psk, Rtty, FT8/4, and the rest.
- **Near-misses with a diagnosed fault:** MT63 1K/500 (one Hadamard row high),
  THOR/DominoEX (tone-step convention), Hell 80 (receive dot clock; the bench
  capture reads), FSQ (wrong varicode), BPSK1000, and the PSK FEC/robust variants
  (no framing/FEC).
- **No decoder:** 8PSK (11 modes), THROB/THROBX, OFDM, SCAMP/SCFSK/SCOOK.
- **ARDOP** samples in `samples/ardop/` were written by `ardopcf` itself and
  decode; the ARQ state machine and TNC are not ported, and control-frame
  detection is code-only.
- **Our Olivia transmitter is still not readable by Jalocha's engine.** That is
  the oldest open interop item and it belongs to this phase.

## The goal, in this order

### A. Receive: every text mode fldigi can send

- **Wire the working decoders into the program first:** the MFSK family,
  MT63-1K/2K, Contestia, and ARDOP. That is UI/engine work, not new DSP, and it
  turns four verified receivers into modes an operator can select.
- **Then fix the near-misses**, in this order: MT63 1K/500, THOR, DominoEX,
  Hell 80, FSQ, BPSK1000, the PSK R/C/F variants. Each starts from the sample and
  the recorded diagnosis.
- **Then implement the missing text modes:** 8PSK, THROB/THROBX, OFDM; decide
  SCAMP/SCFSK/SCOOK by what they actually carry (a verdict is a result).
- Every mode in `samples/fldigi/`, plus fldigi's picture/utility names the corpus
  skipped (WEFAX, IFKP, ANALYSIS, FMT, WWV, SSB, NULL, RSID_EOT), gets one line:
  decoded with the measurement, or a verdict saying what was measured and why not.
- **Three distinct measured attempts per mode**, then move on and write the verdict.

### B. Transmit: parity with fldigi where the mode is a two-way/text mode

- For every mode we can receive, **port the modulator**. The gate is **not** a
  loopback: **fldigi must decode what we transmit** (`ardopcf` for ARDOP). A
  loopback only proves our two halves agree, and the first phase proved that can
  be wrong three ways at once (MFSK varicode, Gray maps, MT63).
- Same for the modes we already transmit: **Olivia first** — our TX is not Olivia
  to anyone else and the vendored engine is the oracle. Then MFSK, MT63,
  Contestia, THOR, DominoEX, Hell, PSK/RTTY/CW, ARDOP.
- **Method:** generate a WAV from our modulator, play it into fldigi through a
  PipeWire null sink and read `text.get_rx`; or transmit from the rig and receive
  on the RSP1 with fldigi decoding. Record the mode, the text and the result in
  the journal.
- **ARDOP:** port the modulator and verify with `ardopcf --decodewav`. The ARQ
  state machine and the TNC host interface are a separate project; do not fake
  them.
- Modes that are inherently receive-only or not text (NAVTEX coast-station
  transmissions, WEFAX pictures, utility analysis modes) get a verdict, not a
  transmitter.

### C. Wire each working mode in

- Appended `Mode` variant, appended `DigiConfig` fields, `PROTO_VERSION` +
  `VERSION_BYTE` bump, panel, band menu, settings. One mode/family per commit.
- Keyboard modes can reuse the text-modem panel shape; MT63/MFSK want variant
  chips (tone/baud/interleave), ARDOP wants its own panel and, later, a TNC.
- No wire field inserted mid-struct or mid-enum; **append only**.

## Sample policy — and this is the permission the operator gave

- **If a sample is suspect, make a new one.** Use fldigi (`sweep.py` / the
  XML-RPC) and record the known text in `manifest.jsonl`; if fldigi is wedged, use
  the reference modulator (`ardopcf --writetxwav`, or a reference implementation)
  and say so in the sample's README row.
- **A sample generated by our own modulator is a plumbing test and never an air
  gate.** It can be committed, labelled as such, and used to debug; it cannot be
  the claim.
- Keep the file names descriptive; no third-party project names in filenames;
  credit in the README's Acknowledgements.

## Rules (the same as this phase)

- **Measure, don't theorise.** Print the intermediate stage; compare sequences,
  not decoded text.
- **Never claim a mode receives without its sample decoding, and never claim it
  transmits without the reference decoder reading our signal.**
- **A test that passes on the broken code is not a test.** Verify fail-first where
  a fault is being fixed.
- `cargo check --workspace --all-targets` silent, rustfmt clean, touched crates'
  tests green. The ignored gates keep defaulting to `samples/`.
- **Journal in `MODE-PROGRESS.md`:** one line per mode, state, the measurement.
  Append as you go — that is where the operator looks, not chat.
- **Commit locally. Nothing is pushed.** One complete thing per commit — what
  works, what does not, and the number that says which.
- If something needs the operator — a decision, hardware, a live transmission —
  put it under **"Needs me"** in the journal and carry on.

## The bench (the operator is giving it)

- RSP1 + CRT SS9900v on VOX; `sdroxide` must be closed while `rspcap` holds the
  RSP1.
- fldigi is the oracle and the recorder: check it is alive first
  (`ss -ltnp | grep 7362`; `MYCALL` set; `PCM` not at zero; `PORTOUTDEVICE` by
  name).
- Our TX to fldigi: a null sink and a capture move; fldigi to us: the sweep and
  the RSP1.
- `ardopcf` builds from `pflarue/ardop` with
  `make CFLAGS="-g -MMD -std=gnu17 -Wno-error=int-conversion -Wno-error=incompatible-pointer-types -Wno-error=implicit-function-declaration"`
  and writes frames with `--writetxwav` / `--decodewav`.
- The corpus's known text is in `samples/README.md`. The first 13 symbols of every
  corpus file are the previous transmission's tail; start at the transmission in
  tests.

## Do not re-derive, it cost this phase days

- **A loopback passes on two halves that share the same wrong convention.**
- **The sample's centre is the middle of the measured tones**, not the manifest or
  the file name.
- **A rig on LSB inverts the tone order**; `reverse` is a station convention, not
  a bug.
- **Read the reference's own arrays/source, not a description of it**: the ARDOP
  leader is the *difference* of its two tones, its type parity starts at 1, and
  its RS block is lowest-degree first with the parity above the message.
- **The reference decoder is the only thing that can settle a convention**; a
  self-consistent port cannot.

**Stop only when every mode has a receive verdict and every text mode we can
receive has a transmitter that fldigi (or `ardopcf`) has read, or the journal says
why not.**
